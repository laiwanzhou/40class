# Thermal C1 invalid imbalanced run audit

The first C1 run was stopped during epoch 6 after trial 1200. Five epochs completed. Its checkpoint, history, and logs are retained locally for audit but are forbidden as resume inputs.

## Root cause

The train loader used natural `shuffle=True` and unweighted cross-entropy even though usable train12 class counts range from 3 to 225, a 75x ratio. Class 36 (`Walk`) accounts for `225/1922 = 0.1170656` of usable train12. That exactly matches the online Train Accuracy in epochs 2 and 3.

The selected epoch-2 checkpoint predicted class 36 for 284 of 377 validation trials and had non-zero recall for only classes 7, 9, and 36. This is a majority-class collapse caused by a training-recipe omission, so the run cannot establish that R(2+1)D-18 failed as a Thermal teacher.

## Implementation integrity

A real R(2+1)D-18 two-clip comparison produced identical loss, logits, all 113 parameter gradients, and BN running buffers for the sequential low-memory backward and a conventional joint graph. The checkpoint remained finite and backbone parameter drift was small. The sequential gradient implementation is not the root cause.

## Correction

The authorized rerun starts again from the exact official Kinetics-400 weights and uses inverse-frequency `WeightedRandomSampler` with replacement over usable train12 class IDs. Each class receives 2.5% sampling probability mass. Validation retains its natural distribution and each validation trial is evaluated once.

The old online training metric is renamed `online_train` because it combines logits generated by changing model states during an epoch. Each corrected epoch records sampled-label and predicted-class histograms.

No heldout label, competition test, IR input, Depth input, or quarantined evidence was read.
